# Handbook implementation plan

> For agentic workers: use superpowers:executing-plans. Implement in this session as authorized by the user, with a final independent review.

**Goal:** Ship a native read-only documentation section with a runnable Clean demo for Umbraco 17 and 18.
**Architecture:** A filesystem document service supplies authenticated Management API endpoints. A Lit client registers a native section, menu/tree, repository and workspace, and renders sanitized Markdown/Mermaid. A once-only migration grants the four agreed standard groups access.
**Tech stack:** .NET 10, Umbraco CMS, TypeScript, Lit, Vite, marked, DOMPurify, Mermaid, YAML metadata, focused .NET/client tests.
**Spec:** ../specs/2026-10-30-handbook-design.md

## Global constraints

- Package Umbraco.Community.Handbook; 18.0.0 on main and 17.0.0 on v17/main with major-bounded dependencies.
- One option: Umbraco:Community:Handbook:DocumentationPath; no search or editing.
- README is its folder page; otherwise generate an immediate-child overview.
- Nine UI locales; native Umbraco navigation and theming.
- Source, image and API access remain inside the configured root and require section access.
- Preserve manual group changes after initial migration, including across major upgrade.
- No publication to NuGet during implementation.

## Review focus

1. Encoded traversal and reparse points must not expose outside files: document service tests.
2. Missing root or malformed frontmatter must not break Umbraco startup: document service tests.
3. Unauthorized API/asset requests must fail: controller and running-site checks.
4. Delayed page responses or broken Mermaid must not replace the active page: client tests/browser checks.
5. Fresh unattended install and 17-to-18 migration must preserve access decisions: integration checks.
